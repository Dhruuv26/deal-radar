# Deal Radar

Price-tracking and deal-scoring platform for computer peripherals sold on Indian
e-commerce sites. Built as a solo Software Engineering course project using an
**Incremental process model** — see `docs/Deal_Radar_SRS.docx` for the full
requirements and `docs/deal_radar_wbs.xml` for the phase breakdown.

## Implementation status: ~30% (Increment 1 complete, Increment 2 scaffolded)

This checkpoint implements **P1: Product Search & Catalog Management** end to
end, plus the *interface* for **P2: Retailer Data Ingestion** backed by a mock
client (see below for why). Nothing beyond that is built yet.

| Feature (SRS §4) | Status |
|---|---|
| P1 — Product Search & Catalog Management | ✅ Implemented (REQ-P1-1 through REQ-P1-4), with tests |
| P2 — Retailer Data Ingestion | 🟡 Interface + mock client only, not wired to real APIs |
| P3 — True Price & Deal Score Computation | ⬜ Not started |
| P4 — Review Signal Analysis | ⬜ Not started |
| P5 — Watchlist & Alerts | ⬜ Not started |
| P6 — Dashboard & Comparison | ⬜ Not started (only the P1 search/add screen exists) |

**Why P2 is mocked rather than skipped:** Amazon PA-API access depends on
affiliate approval that's still pending (SRS Appendix C, TBD-1). Rather than
block all backend progress on that external dependency, `app/services/ingestion.py`
defines the `RetailerAPIClient` interface P2 will implement against, with a
`MockRetailerClient` returning realistic sample data. When API access is
confirmed, a real client implementation drops in without changing anything
else in the system.

The database schema (`app/models.py`) already includes all 8 entities from
the ER Diagram — `PriceSnapshot`, `Offer`, `ReviewSignal`, and `DealScore`
tables exist but aren't populated yet, since those belong to P2–P4.

## Running it

### Backend

```bash
cd backend
python -m venv venv
source venv/bin/activate        # venv\Scripts\activate on Windows
pip install -r requirements.txt
python -m app.seed              # creates deal_radar.db, seeds categories + retailers
uvicorn app.main:app --reload
```

API docs (auto-generated by FastAPI) are then at `http://127.0.0.1:8000/docs`.

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173`. The backend must be running on port 8000 first
(`api.js` points at `http://127.0.0.1:8000`).

### Tests

```bash
cd backend
source venv/bin/activate
pytest tests/ -v
```
